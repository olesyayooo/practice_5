## Вариант 6

Недельная норма составляет 35 часов. Недельная переработка: max(0, сумма − 35). Дневная норма — 8 часов. Допустимые значения — целые числа от 0 до 16 включительно, ровно пять значений через точку с запятой. Пробелы по краям значений удаляются. Повторяющиеся часы разрешены: каждый элемент относится к отдельному дню.

Пример ввода: 8;8;8;8;8

Результат: сумма 40, среднее 8.0, дней с переработкой 0, недельная переработка 5.

## Ошибка предложенного фрагмента

При i <= hours.length цикл обращается к hours[5], хотя допустимые индексы массива из пяти элементов — от 0 до 4. Возникает ArrayIndexOutOfBoundsException. Правильно:

```java
for (int i = 0; i < hours.length; i++) {
    total += hours[i];
}
```

## Собственные формулировки

**Какая проверка защищает от наиболее вероятной ошибки ввода и где расположена?** В TimesheetAnalyzer.parseHours проверяются число полей, целочисленный формат и диапазон 0–16. Ошибка содержит номер позиции. split(";", -1) сохраняет пустое последнее поле, поэтому пропущенный пятый день не теряется.

**Где находится ключевое бизнес-правило?** В TimesheetAnalyzer.weeklyOvertime вычисляется недельная переработка. Норма берётся из TimesheetAnalyzer.WEEKLY_NORM: расчёт отделён от ввода, а значение правила хранится в одном месте.

**Как Activity-диаграмма отражает участок кода?** Проверка i < parts.length, обработка поля и увеличение i соответствуют циклу for в TimesheetAnalyzer.parseHours. После проверки всех значений программа рассчитывает показатели. Сумма считается циклом for, число дней с переработкой — циклом while.

**Какое изменение должно затронуть минимум классов?** Изменение недельной нормы требует изменить только WEEKLY_NORM в TimesheetAnalyzer. Код расчёта и ввода менять не нужно; ожидаемые результаты зависящих от нормы тестов надо обновить.

## Структура

Main — ввод и вывод; TimesheetAnalyzer — параметры, разбор и расчёты; SelfCheck — исходная проверка преподавателя; ExtraCheck — собственные проверки. Расчётные методы получают проверенный массив из parseHours. Если ввод некорректен, массив не возвращается и вычисления не выполняются. Сообщается первая найденная ошибка.

Диаграммы: activity.svg и classes.svg. Протокол: TEST_RESULTS.txt. В успешных собственных проверках порядок результатов: сумма, среднее, дни с переработкой, недельная переработка. Проверены 0, 16, 17, отрицательное число, пустая строка, null, буквы, дробь, переполнение int, пустые поля, лишний и пропущенный день, пробелы, повторяющиеся значения и границы недельной нормы.

## Кратко для защиты

Программа разбивает строку табеля на пять полей, проверяет каждое и сохраняет часы в массив int[]. Отдельные методы считают сумму, среднее, количество дней свыше восьми часов и превышение недельной нормы 35 часов.

Среднее рассчитывается с приведением к double, чтобы не потерять дробную часть. При сумме 36 среднее равно 7.2. Дневная и недельная переработка независимы: 9;8;0;10;7 содержит два дня с переработкой, но сумма 34 не превышает недельную норму.
